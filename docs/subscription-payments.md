# 订阅、支付与AI用量

## 产品方案

工作区按30天购买订阅，数字员工的文本调用、图片理解与视频生成共享AI点数。此版支持微信Native扫码、支付宝当面付扫码，用户主动购买与续订，不涉及免密或自动扣款。

默认建议方案（管理员可调整）：

| 套餐 | 30天售价 | AI点数 | 全部用于视频时的模型生成量 | 对应模型成本上限估算 |
| --- | ---: | ---: | ---: | ---: |
| 轻运营版 | 199元 | 6,000 | 120秒 | 60元 |
| 增长版 | 599元 | 20,000 | 400秒 | 200元 |
| 矩阵版 | 1,499元 | 60,000 | 1,200秒 | 600元 |

上表按默认点数规则计算，混合使用文本和视频时视频秒数会减少；不是成片数量承诺。默认模型成本分别为视频0.5元/生成秒、文本输入2元/百万Token、输出10元/百万Token。默认扣减分别为50点/生成秒、200点/百万输入Token、1000点/百万输出Token。

点数是订阅用量单位，不是货币、不可提现。套餐收入用于覆盖模型、服务器、浏览器运行、存储、支付手续费、税费和服务支出；上表成本仅包含模型，不是净利润预测。套餐目前按用量区分，不额外改变矩阵账号数等现有功能权限。

首次支付确认后开始30天周期；续订从最后一期结束后开始，允许提前续订。每期额度独立，到期不结转。当前未提供即时加量包或升级折算，本期不足时等待新周期或联系平台。上线前应根据真实用量调整套餐，并在购买页面保留期限和计量说明。

## 使用入口

- 用户侧：左侧“费用”改为“订阅”，地址 /subscription，旧 /costs 自动跳转。展示本期剩余/已用/预留额度、后续周期、套餐、扫码付款、主动查单、分页订单和分页用量。工作区负责人及有订阅管理权限者可购买，其他有订阅查看权限者可查看。
- 管理员侧：“平台管理 → 支付与订阅”，配置并启停渠道、设置成本及点数规则、维护套餐、查看跨企业订单和模型成本、处理不确定用量。
- 支付和AI账本按企业隔离。前端不能决定金额、开通订阅、修改点数或标记支付成功。

## 商户接入

微信使用API v3直连商户Native支付、公钥模式：填写微信应用App ID、商户号、商户API证书序列号、32位API v3密钥、商户API私钥、微信支付公钥ID和微信支付公钥。应用和商户须具有对应产品权限；此版未实现服务商/特约商户模式和平台证书自动下载轮换。

支付宝使用当面付预创建订单、RSA2公钥模式：填写应用App ID、商户UID、应用私钥、支付宝公钥及通知地址。此版不支持支付宝证书模式；配置中的返回地址可选，扫码支付不依赖网页跳转证明付款。

生产通知地址：

- 微信：https://campfire.dawoai.com/api/v1/payments/wechat/notify
- 支付宝：https://campfire.dawoai.com/api/v1/payments/alipay/notify

通知地址须公开HTTPS可达，并由网关原样转交请求正文及签名头；不要给通知路径添加登录拦截、页面挑战或重定向。密钥仅在服务器加密存储，不回显；留空保留旧值，勾选清除才移除。须备份平台加密主密钥，丢失后不能解密支付配置。在存在未结订单时不要更换商户身份或直接覆盖验签公钥；此版没有历史密钥环，切换前先核对未结订单并安排维护窗口。

参考协议为微信支付Native / API v3与支付宝alipay.trade.precreate、alipay.trade.query和RSA2异步通知。保存配置只做格式校验，不证明商户已开通；生产必须用真实商户进行小额交易验收。

## 支付一致性

订单金额使用人民币整数分，在服务器从当前上架套餐读取；价格、额度和用户扣减规则快照到订单与订阅周期。后台调价或下架不改变已购周期。内部成本按调用时参数快照估算。

下单先保存本地订单再请求渠道，前端同一次购买使用幂等标识；每企业15分钟内仅允许一个在途订单。二维码在本地生成，不向第三方二维码服务发送付款链接。微信验证响应及通知签名，并用AES-GCM解密通知；支付宝验证响应及通知RSA2签名。核对商户、应用、交易状态、订单、币种及金额后，事务内开通一期权益。相同通知、交易和查单不会重复开通。迟到但被渠道确认的付款仍开通权益。

前端每5秒读取本地订单状态，不反复请求支付渠道；“我已支付，查询结果”主动查单在服务器按订单限流10秒。下单结果不确定可从订单记录恢复查单，前端不会自行宣告支付成功。

本版没有自动退款、自动对账任务、发票或退款后自动扣回权益。退款须在商户后台处理，并单独核对订阅权益，不能只退钱不处理权益。生产运营前需要制定退款与售后处理流程。

## AI计量与失败恢复

所有现有收费模型入口已接入：数字员工岗位交付、GEO文案整理、素材图片理解、分镜视频生成。

- 调用前按企业行锁序列化预留额度，防止并发申请穿透余额。没有有效订阅或额度不足时，启用付费拦截后返回402，不发模型请求。
- 文本预留使用保守输入上界和max_tokens，结算以上游实际prompt_tokens/completion_tokens为准。最小用量保留到百万分之一点，避免每次小额Token四舍五入。
- 视频按成功生成的请求时长计量。生成5秒、成片只保留2秒，计5秒；已有分镜复用、恢复轮询和再次下载不重复收生成点数。上游不支持按最终成片长度倒扣。
- 明确拒绝或生成失败释放额度；超时、网络断开、上游缺少Token用量等不确定状态保留预留，等待继续取结果或人工核对。主动重新提交是一次新的调用，原不确定调用另行核对。
- 管理员可在用量列表填入真实Token/秒数结算，或填写核对依据释放。未明确未知的在途预留须满1小时才能处理。操作留审计，终态不可重复扣减或释放。
- 极端情况下上游实际Token超过保守预留，仍如实记录实际用量，不丢账；该期可能出现欠额，剩余显示0，后续调用被阻止，需管理员核对。上游成本估算不等于中转账单的最终扣款。
- 观察模式默认关闭付费拦截，记录但不限制存量客户。观察模式用量没有订阅时不追溯扣到后来购买的周期。新账本不自动重算历史模型调用。

发布账号授权、作品数据采集、素材存储等服务成本目前包含在订阅售价中，没有独立按次扣点。没有AI调用的纯复用任务不消耗模型生成点数。
