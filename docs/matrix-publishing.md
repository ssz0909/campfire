# 多账号矩阵发布

「平台发布」中选择抖音或视频号、填写账号备注后添加账号，在对应账号卡片打开云端网页登录并扫码。账号备注用于业务识别，请核对云端实际登录身份；可修改备注。每个账号单独保存登录状态，退出只清除该账号的会话，过期后重新登录原账号。若平台暴露稳定账号标识，系统绑定其摘要，发布或采集发现身份变化时停止，避免串号。未读取到稳定标识时依赖隔离会话，人工核对身份仍必要。

新建普通/定时任务选择具体发布账号，可同时选「抖音1＋视频号1」，也可选单独的「抖音2」或「视频号2」。任务保存账号ID，沿下游员工任务传递；每次定时实例保留相同目标账号。总任务审批后可在详情补选账号继续闭环；已经创建发布记录后不能改变目标账号，需另建任务。

成片审核页面显示目标账号。审核通过后每个账号生成一条独立发布记录，幂等键包含账号ID。发布记录显示账号、状态和结果，单账号失败不影响其他账号。重新发布保留原账号；数据回流使用发布记录绑定账号的会话并记录账号ID。当前采集仍为账号级指标，不能当作单条作品归因。

浏览器操作共用串行工作线程，每个账号独立persistent profile，按需恢复。最多保留两个打开的浏览器上下文；打开第三个账号前释放已确认保存会话的窗口。两个窗口尚未完成登录时需先完成登录。此限制不限制已保存账号数量。云端画面可能因窗口自动释放而需重新打开，不影响已保存登录信息。

2026-11-03：抖音身份改为通过已登录会话只读访问 `/web/api/media/user/info/`，对返回的用户 UID 生成 `webuidsha256:` 摘要；不再将可能变化的 `uid_tt` Cookie 当作固定身份。旧绑定仅在原 Cookie 摘要仍匹配时自动升级，无法证明对应关系时保留拦截；人工确认过的历史误判须针对具体账号核对平台 UID 后修复，不能全局清空绑定。昵称仅用于展示，不参与身份判断。真实账号切换仍会拦截，发布和数据同步前重新校验。

已验证身份随加密会话保存。浏览器窗口释放后，已验证、已保存的账号仍显示“可发布”，同时标明“发布前自动校验”；这表示可用于发布任务，并非保证会话永久有效。未经身份验证的旧会话仅显示“会话已保存”。实际发布仍恢复对应隔离浏览器并检查平台登录和绑定 UID。

恢复浏览器后，发布及数据读取会等待平台页面与账号身份加载（默认15秒，有限重试），避免在 SPA 刚返回文档时误判账号不一致。只有读到不匹配的账号指纹才报告身份不一致；明确出现登录界面才提示重新登录。身份暂时不可读时停止上传和提交，提示稍后重试，无需退出；不会修改已绑定账号或使用旧身份绕过校验。

前端定时检查包含 `session_saved` 账号，避免在过渡状态停止刷新；打开一个账号后同步检查其他已登录/已保存账号，及时反映窗口释放。按账号记录请求序号，忽略晚返回的旧状态。构建后执行 `backend/.venv311/bin/python frontend/tests/matrix-account-ui.py`，以模拟接口验证顺序打开三个账号、释放第一个窗口后保留可发布，以及保存状态恢复后无需刷新页面即可更新。

迁移20261030_matrix_accounts移除企业＋平台唯一约束，增加label/session_profile。原有连接profile保持NULL继续读取原目录；旧任务与定时计划按迁移前平台连接固定账号ID；旧发布记录不改动。新增账号profile使用独立UUID，存放platform-sessions/{company}/{platform}-accounts/{profile}/，不在旧目录内，防止退出原账号删除其他会话。多账号场景旧的平台级接口不猜账号，必须传connection_id；新增GET/POST publishing/accounts、PATCH publishing/accounts/{id}。

部署前备份数据库和代码，停止任务空闲的服务，运行alembic upgrade head后启动服务。回退时若同平台已有多个账号，迁移明确拒绝删除多余账号，须先处理数据，不能直接downgrade。
