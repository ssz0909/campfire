# 数字员工交付校验与失败恢复

## 岗位边界

- 运营总管、数据分析员、内容策划、运营助理交付报告和下一步工作要求。可提供镜头创意，不要求填写正式分镜字段。
- 非视频岗位返回的 `video_storyboard` 作为文字建议进入报告，不进入可执行分镜，也不直接创建视频项目。
- 视频制作员使用正式分镜协议；质量优先与成本优先各自使用原有校验器。素材候选范围、时长、重复引用、人物首镜等约束保持有效。
- 岗位 JSON Schema 随系统提示下发；后续岗位白名单、审批、租户隔离继续由工作流控制。

## 有限纠正

收到交付后先验证 JSON、字段结构及视频制作约束。无效时携带字段路径和错误类型请求一次纠正；纠正仍失败则停止。不会凭空填素材 ID、补零或将无效分镜降级为可执行成片。

连接错误、鉴权错误、接口超时不触发此纠正重试。每次实际文本调用仍走原有用量计量，成功交付汇总两次 Token 和估算成本。纠正可能增加一次文本模型调用。

校验失败的字段路径和类型写入服务日志，不输出完整模型原文。客户收到简短的任务失败信息，不再显示 Pydantic 堆栈及文档链接。

## 验收

- 七条只有时间段、画面建议和素材准备状态的运营策划不会触发 49 项正式分镜字段缺失；建议完整保留供下游使用。
- 顶层与章节中的策划分镜均可处理；正式分镜的字段冲突仍拒绝。
- 无效 JSON 最多纠正一次；文本用量累计；网络超时仅尝试一次。
- 质量及成本模式中，候选池外素材无法通过校验；纠正成功后再继续工作流。
- 原有审批、后续派发及制作发布闭环测试通过。

本机制解决岗位协议混用并降低模型格式波动造成的失败，不保证外部模型或网络永不报错。旧任务需要在部署后重新执行，不直接修改历史失败状态。

## 视频策划与制作容量统一

`video_capacity.py` 为运营策划、派发和视频制作提供同一容量合同，放入 `video_brief`，不依赖大模型自行估算。只统计当次任务实际可用的、已识别或人工分类且满足基础画质/选材规则的不同图片；不是素材库总数。

- 质量优先：首镜不超过2秒，其余每镜不超过3.5秒，每张图片最多一次；最低图片数为 `max(5, 1 + ceil((时长 - 2) / 3.5))`。
- 成本优先：每张参考图对应一个5秒片段，末段按成片时长剪取，最低图片数为 `ceil(时长 / 5)`；片段内部可以有1至2个同场景景别。
- 用户要求固定时长：不足时提前交付具体缺口，不擅自缩短或切换模式；策划不能继续派发必然失败的视频制作任务。
- 用户要求时长范围：保留范围，在范围内按素材量确定可行的整数秒目标。9张图、质量优先、30至45秒要求会规划30秒，45秒固定要求则缺5张。
- 未指定时长：默认希望制作30秒，可在15至30秒内按素材容量规划。
- 派发携带原始时长意图与已计算的目标，制作时重新核对当前素材；旧闭环任务会从同租户根任务恢复被旧解析丢失的范围，而不会修改历史审批内容或自动重跑任务。
- 策划提示词接收容量约束，后端派发再次检查可行性；质量和成本校验器继续拒绝重复图片及候选池外素材。

验收覆盖：30-45/30至45/30—45/30秒到45秒范围、固定时长不足、两种模式数量差异、容量极限可执行、策划到制作参数一致、旧派发范围恢复、素材不足禁止两种派发路径。

## 画面比例与配乐选项

新建视频及数字员工任务均支持9:16、16:9、1:1，旧任务默认9:16。定时计划编辑回显并保存该值，子任务逐级传递，策划提示词和video_brief使用相同比例，创建VideoProject时保留比例；后续沿用已有的参考图裁切、模型请求、剪辑和品牌文字自适应逻辑。选材画质同等时优先匹配目标画幅，库存片段仍按原有画幅合同校验。

工作区与任务使用同一套基础配乐选项：素材库随机、固定音乐、静音、保留模型原声。任务额外提供“跟随工作区设置”。工作区保存原声模式时清空旧音乐ID及静音标记；任务可独立覆盖，不改变工作区默认。保留模型原声沿用现有模型音轨开关，并不提供统一音色解说或语音合成能力。已创建项目保留原配置。

验收：三种画幅从策划、派发到项目一致；定时任务编辑与立即执行保留画幅；无效画幅返回422；同等图片按目标画幅优选；原声默认保存及任务覆盖；浏览器实测两个创建入口比例选择与工作区原声保存。
