# 平台登录会话校验

抖音与视频号均通过已有会话调用平台自身的只读身份接口，不以页面文字、菜单、DOM 结构或 localStorage 中的账号名作为登录成功凭据。

- 抖音：`GET https://creator.douyin.com/web/api/media/user/info/`，成功响应必须包含稳定 UID。
- 视频号：`POST https://channels.weixin.qq.com/cgi-bin/mmfinderassistant-bin/auth/auth_data`，成功响应必须包含 `finderUser.finderUsername`。请求使用用户正常登录时捕获、加密保存的身份请求参数。
- 接口返回的稳定标识经摘要后与矩阵账号绑定比对。账号身份不同则停止发布和采集，不自动替换原绑定。
- 关闭登录窗口后也可以用已保存的会话进行 HTTP 校验，不启动浏览器。不因文件中存有 Cookie 或旧的 `identity_verified` 字段就直接认定可发布。

状态响应新增 `auth_source=web_api`、`auth_state`。`verified` 为接口已验证；`expired` 为平台明确返回过期（HTTP 401 或已知过期码）；`unverified` 为接口未就绪、网络失败、限流或无法确认。暂时无法校验会保留加密会话，并通过现有待登录状态和“无需退出账号”的消息提示等待校验；只有明确失效才提示重新登录。主动退出登录仍只清理对应账号。

状态轮询缓存成功结果最长60秒，失败缓存3秒。缓存按企业/平台/账号隔离，并对当前 Cookie 和身份请求参数求摘要，凭据变化后立即重新请求。发布或浏览器采集开始前强制清除短时缓存，校验接口身份后才允许上传。模板或凭据缺失不使用页面文字兜底。

这减少平台 UI 改版造成的误判，但平台身份接口本身的地址、请求协议或返回结构变化时，仍需维护适配器。实际发布的上传、文案和地点操作仍沿用浏览器，不属于登录状态识别。

验证：`backend/tests/test_web_auth.py` 覆盖双平台、DOM 不可读、凭据变化、缓存刷新、过期/限流/网络异常、会话保存、错误身份和地址白名单；账号矩阵与浏览器采集测试覆盖流程兼容性。
