# 运营执行闭环

新建任务勾选“启用运营闭环”，选择抖音、视频号或两个平台。由运营总管起步的流程：

1. 总管目标草稿 → 人工审批 → 数据分析员。
2. 分析员解析本年、月份或明确日期，按缺口补同步订单。覆盖不足会阻塞下游，不能把样本视为全年结论。连接器修复后，在总任务点击“继续 / 修复执行流程”重新分析。
3. 分析审批 → 内容方案审批 → 视频脚本审批。岗位流转由服务端固定推进，不依赖模型返回的 next_actions。
4. 视频脚本审批明确授权启动付费生成；默认5秒、9:16。生成完成后预览并审核成片。
5. 成片审核创建所选平台各一份发布审批；审批页展示具体标题、正文、平台并链接成片。发布权限用户通过审批后才调用 Web 发布。
6. 平台可见结果确认成功后记录 published。登录过期、验证或结果不确定时标记需处理，不冒充发布成功。重新执行前需核对平台，避免重复发布。
7. 成功发布24小时后，后台每分钟检查到期任务，采集账号级指标。失败按1小时间隔重试，最多3次，之后提示人工处理；也可手动“刷新平台数据”。服务重启后仍依据数据库中的到期时间继续。
8. 首次获得数值指标后，每个发布任务只创建一份关联复盘任务。复盘提出下一轮优化计划，人工审批通过后，本轮才标记“已闭环”。新一轮需另建任务，避免无界付费和发布。

## 旧任务

原先已完成但停留在报告的总任务可点击“启动执行闭环”，选择平台，补建新的分析阶段；保留旧报告。不会因升级自动调用付费生成或发布。已创建发布审批后，不允许直接修改总任务的目标平台。

## 状态与恢复

岗位“完成”仅表示该岗位草稿获批，总任务详情单独显示整链路状态和阶段链接。待审批阶段不自动越过。未派发的 pending 阶段可通过继续恢复；失败任务使用重新执行，生成失败在视频项目重试。取消总任务阻止后续模型调用和发布；已提交到外部平台或模型的请求不能撤回。

`EXECUTION_AUTOMATION_ENABLED=true`（默认）开启后台回流；多进程使用 PostgreSQL advisory lock 防止重复采集。生产仍需运行后端；Celery 模式另需正常队列与工作进程。

## 验证边界

账号数据不等于单作品效果，无法据此声称ROI、单条作品转化或酒店收入增长。Web 发布与采集依赖平台页面及登录状态；验证/选择器失效会保留人工处理入口。测试模拟外部模型和平台，不实际消耗生成额度或发布内容。
